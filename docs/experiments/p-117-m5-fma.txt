# WHAT THE VACUITY CONTROL DID HERE, AND WHY THIS FILE IS THE ONLY PLACE IT COULD.
# The registration requires the KNOWN-FUSED probe to be seen fusing ON AARCH64, and this
# is the arm where it is visible in the probe's own body: `fmadd` is baseline A64, so
# `p117_probe_known_fused` disassembles to exactly
#
#     fmadd  d0, d0, d1, d2
#     ret
#
# On x86-64 FMA3 is not in the baseline ISA, so the identical source tail-jumps into
# `compiler_builtins`' runtime-dispatched `fma` and the hardware instruction sits one
# level away in `fma_with_fma` as `vfmadd213sd`. Both are fusion -- one rounding where
# the written form has two -- but only this arm shows it in place, which is exactly why
# the registration put the control here. `fma_in_known_fused_probe=1` with
# `known_fused_probe_evidence=fmadd` is the control firing.
#
# AND WHAT IT PROVED ABOUT THE CRATE. On the same machine, compiled by the same rustc in
# the same binary, the plain `a * b + c` does NOT fuse:
#
#     __ZN15experiment_p11718p117_probe_written:
#         fmul  d0, d0, d1
#         fadd  d0, d0, d2
#         ret
#
# and neither does `cube::place`:
#
#     __ZN15experiment_p11716p117_probe_place:
#         fadd  d3, d0, d1
#         fmov  d4, #0.50000000
#         fmul  d3, d3, d4
#         fsub  d0, d1, d0
#         fmul  d0, d0, d2
#         fadd  d0, d3, d0
#         ret
#
# nor the 2x2 determinant shape `a*b - c*d` (`vec3::cross`, `Symmetric3::adjugate`):
#
#     __ZN15experiment_p11716p117_probe_cross:
#         fmul  d0, d0, d1
#         fmul  d1, d2, d3
#         fsub  d0, d0, d1
#         ret
#

# `fma_instructions_isomesh_extract=0` over 9 monomorphised extractors say the same thing
